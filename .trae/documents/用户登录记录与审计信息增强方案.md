# 用户登录记录与审计信息增强方案

## 一、现状分析

### 1.1 已有的记录机制

| 机制 | 说明 | 覆盖范围 |
|------|------|----------|
| `LoginAttemptEntity` | 记录密码登录的失败尝试和锁定状态 | 仅密码登录 |
| `AuthMetrics` (OpenTelemetry) | 记录登录成功/失败计数、耗时直方图 | 所有登录方式 |
| `ILogger` 日志 | 结构化日志记录关键操作 | 所有登录方式 |
| `CorrelationIdInterceptor` | 请求关联ID追踪 | 所有 gRPC 请求 |

### 1.2 现有实体结构

#### LoginAttemptEntity（登录尝试/防暴力破解）
```csharp
public class LoginAttemptEntity
{
    public Guid Id { get; set; }
    public string Username { get; set; } = string.Empty;
    public DateTimeOffset LastAttemptAt { get; set; }
    public int FailedAttempts { get; set; }
    public DateTimeOffset? LockoutUntil { get; set; }
}
```
**问题**：该实体设计目的是**防暴力破解**，而非**审计记录**。它只保留每个用户的最新状态，不保留历史记录。

#### AccountEntity（用户账户）
```csharp
public class AccountEntity
{
    public Guid Id { get; set; }
    public bool IsActive { get; set; } = true;
    public DateTime CreatedAt { get; set; }
    public string? Remark { get; set; }
    public string? Nickname { get; set; }
}
```
**问题**：缺少 `LastLoginAt`、`LastLoginIp` 等字段。

### 1.3 关键缺失项

| 缺失项 | 影响 | 严重程度 |
|--------|------|----------|
| **登录历史记录表** | 无法查询用户何时、从何处登录 | 🔴 高 |
| **审计日志表** | 无法追踪账户变更操作（创建、修改、禁用等） | 🔴 高 |
| **IP 地址记录** | 无法做异地登录检测、安全分析 | 🔴 高 |
| **User-Agent / 设备信息** | 无法识别登录设备 | 🟡 中 |
| **账户最后登录时间** | 无法显示用户活跃度 | 🟡 中 |
| **退出登录记录** | 无法追踪会话生命周期 | 🟡 中 |
| **Admin API 操作审计** | 管理员操作无留痕 | 🔴 高 |

## 二、增强方案

### 2.1 方案概述

采用**"登录历史 + 审计日志"双表策略**，分别记录：
- **登录历史 (`LoginHistoryEntity`)**：记录每次登录/登出事件，用于安全分析和用户查询
- **审计日志 (`AuditLogEntity`)**：记录所有敏感操作（创建用户、修改状态、重置密码等），用于合规和追责

### 2.2 新增实体设计

#### 2.2.1 LoginHistoryEntity（登录历史）

```csharp
namespace QuantumZhou.Identity.Database.Entity;

public class LoginHistoryEntity
{
    public Guid Id { get; set; }
    
    /// <summary>关联账户ID</summary>
    public Guid AccountId { get; set; }
    
    /// <summary>登录方式：password, sms, wechat, refresh_token</summary>
    public string AuthMethod { get; set; } = string.Empty;
    
    /// <summary>事件类型：login_success, login_failure, logout</summary>
    public string EventType { get; set; } = string.Empty;
    
    /// <summary>客户端IP地址</summary>
    public string? ClientIp { get; set; }
    
    /// <summary>User-Agent</summary>
    public string? UserAgent { get; set; }
    
    /// <summary>失败原因（仅失败时）</summary>
    public string? FailureReason { get; set; }
    
    /// <summary>关联的AppId（如果有）</summary>
    public string? AppId { get; set; }
    
    /// <summary>事件时间</summary>
    public DateTimeOffset CreatedAt { get; set; }
}
```

**索引设计**：
- `account_id` + `created_at`（用户查询登录历史）
- `created_at`（定时清理旧数据）
- `client_ip`（安全分析）

#### 2.2.2 AuditLogEntity（审计日志）

```csharp
namespace QuantumZhou.Identity.Database.Entity;

public class AuditLogEntity
{
    public Guid Id { get; set; }
    
    /// <summary>操作类型：account_created, account_updated, account_disabled, password_changed, app_registered 等</summary>

    /// <summary>操作对象类型：Account, AppRegistration, RefreshToken 等</summary>
    public string TargetType { get; set; } = string.Empty;
    
    /// <summary>操作对象ID</summary>
    public string TargetId { get; set; } = string.Empty;
    
    /// <summary>操作人账户ID（系统操作则为null）</summary>
    public Guid? ActorId { get; set; }
    
    /// <summary>操作人身份标识（如管理员用户名、系统任务名）</summary>
    public string? ActorName { get; set; }
    
    /// <summary>操作前数据快照（JSON）</summary>
    public string? BeforeSnapshot { get; set; }
    
    /// <summary>操作后数据快照（JSON）</summary>
    public string? AfterSnapshot { get; set; }
    
    /// <summary>操作描述</summary>
    public string? Description { get; set; }
    
    /// <summary>客户端IP</summary>
    public string? ClientIp { get; set; }
    
    /// <summary>操作时间</summary>
    public DateTimeOffset CreatedAt { get; set; }
}
```

**索引设计**：
- `target_type` + `target_id` + `created_at`（查询特定对象的变更历史）
- `actor_id` + `created_at`（查询操作人的操作记录）
- `action` + `created_at`（按操作类型查询）
- `created_at`（定时清理）

### 2.4 gRPC 客户端信息获取

gRPC 的 `ServerCallContext` 提供 `Peer` 属性（格式如 `ipv4:127.0.0.1:12345`），但需要额外处理：

```csharp
public static class GrpcContextExtensions
{
    public static string? GetClientIp(this ServerCallContext context)
    {
        // 优先从自定义 Header 获取（经过反向代理时）
        var forwardedIp = context.RequestHeaders
            .FirstOrDefault(h => h.Key.Equals("x-forwarded-for", StringComparison.OrdinalIgnoreCase))?.Value;
        if (!string.IsNullOrEmpty(forwardedIp))
            return forwardedIp.Split(',')[0].Trim();
        
        // 从 Peer 解析
        var peer = context.Peer;
        if (peer.StartsWith("ipv4:") || peer.StartsWith("ipv6:"))
        {
            var parts = peer.Split(':');
            if (parts.Length >= 3)
                return string.Join(":", parts[1..^1]); // 处理 IPv6
        }
        return peer;
    }
    
    public static string? GetUserAgent(this ServerCallContext context)
    {
        return context.RequestHeaders
            .FirstOrDefault(h => h.Key.Equals("user-agent", StringComparison.OrdinalIgnoreCase))?.Value;
    }
}
```

### 2.5 数据保留策略

```csharp
public class AuditLogRetentionOptions
{
    /// <summary>登录历史保留天数（默认90天）</summary>
    public int LoginHistoryRetentionDays { get; set; } = 90;
    
    /// <summary>审计日志保留天数（默认365天）</summary>
    public int AuditLogRetentionDays { get; set; } = 365;
}
```

在 `CleanupWorker` 中增加定时清理任务：

```csharp
public class CleanupWorker : BackgroundService
{
    // ... 现有清理逻辑 ...
    
    private async Task CleanupAuditLogsAsync(CancellationToken stoppingToken)
    {
        var loginCutoff = DateTimeOffset.UtcNow.AddDays(-_retentionOptions.LoginHistoryRetentionDays);
        var auditCutoff = DateTimeOffset.UtcNow.AddDays(-_retentionOptions.AuditLogRetentionDays);
        
        await _auditLogRepository.RemoveOldLoginHistoryAsync(loginCutoff);
        await _auditLogRepository.RemoveOldAuditLogsAsync(auditCutoff);
    }
}
```

## 三、实施步骤

### Phase 1：核心数据模型（1-2天）
1. 创建 `LoginHistoryEntity` 和 `AuditLogEntity`
2. 扩展 `AccountEntity`（增加 `LastLoginAt`, `LastLoginIp` 等字段）
3. 更新 `IdentityDbContext` 和数据库迁移
4. 创建对应的 Repository 接口和实现

### Phase 2：登录记录（1-2天）
1. 实现 `AuditService`
2. 改造 `AuthServiceImpl.GetToken`：在登录成功/失败时记录 `LoginHistory`
3. 改造所有 Validator：在验证失败时记录失败原因
4. 更新 `Account` 最后登录信息
5. 实现 gRPC 客户端信息提取工具类

### Phase 3：审计日志（1-2天）
1. 改造 `AdminApi`：在所有写操作后记录 `AuditLog`
2. 改造 `AuthServiceImpl`：在令牌吊销、回调注册等操作后记录审计
3. 为自动注册（SMS/WeChat）记录审计日志

### Phase 4：查询接口与清理（1天）
1. 实现 `AdminApi` 查询接口（登录历史、审计日志）
2. 扩展 `CleanupWorker` 增加数据清理逻辑
3. 配置保留策略选项

### Phase 5：测试与验证（1-2天）
1. 单元测试：`AuditService` 逻辑
2. 集成测试：登录后验证数据库记录
3. 验证清理任务正常工作

## 四、风险与注意事项

| 风险 | 缓解措施 |
|------|----------|
| 高频登录导致数据量过大 | 配置合理的保留策略 + 定时清理 |
| 审计日志写入影响性能 | 使用异步写入 + 批量插入（未来可考虑消息队列） |
| 敏感信息泄露 | `BeforeSnapshot`/`AfterSnapshot` 中不记录密码哈希等敏感字段 |
| 反向代理下 IP 获取不准 | 支持 `X-Forwarded-For` Header，可配置信任代理列表 |

---

## 五、总结

当前项目的登录记录能力**不足以支撑生产环境的安全审计需求**：
- ✅ 有防暴力破解机制 (`LoginAttemptEntity`)
- ✅ 有指标监控 (`AuthMetrics`)
- ❌ **无登录历史记录**
- ❌ **无审计日志**
- ❌ **无 IP / 设备信息记录**
- ❌ **无账户最后登录时间**

建议按上述 **Phase 1-5** 逐步实施，优先完成 **登录历史记录**（安全刚需）和 **Admin API 审计**（合规刚需）。
